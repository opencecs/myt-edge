# Y12 远程桌面串流实测

Y12 固件 20261119-r292，Docker 27.3.1。两路 Windows 客户端经 SSH 同时从板上接收并解码各自的桌面。两组使用同一镜像、1080p30、MVX H.264、3 Mb/s 目标码率、无 B 帧。每个桌面运行独立的终端时间图案，稳态统计窗口 20 秒。

| 合成器 | 桌面 | 接收 fps | 首帧 ms | 画面到解码 P50 / P95 ms | 容器 CPU（单核为 100%） |
| --- | --- | ---: | ---: | ---: | ---: |
| Mali GLES2 | A | 30.00 | 581 | 217 / 228 | 77.41% |
| Mali GLES2 | B | 29.98 | 608 | 217 / 228 | 77.35% |
| Pixman | A | 30.01 | 633 | 214 / 225 | 79.64% |
| Pixman | B | 30.01 | 609 | 214 / 226 | 79.69% |

板上日志确认两路 GLES2 renderer 为 Mali-G720-Immortalis，两个编码会话使用 MVX /dev/video1。CIX GBM 在容器中缺失 /dev/dma_heap/system 时初始化失败。单独映射该节点后，Sway 创建了 Mali GLES2 渲染器和 1920×1080 GBM 缓冲区。桌面捕获仍经过系统内存，RGB 到 NV12 仍由 CPU 转换。

延迟由画面中的时间戳和 Windows 客户端解码后读出时间计算。两端时钟通过同一 SSH 链路采样校准，最短往返约 0.14 ms。结果包含画面更新、捕获、编码、传输和解码，不包含客户端屏幕显示、键鼠往返或显示器响应。CPU 用容器 cgroup 的 usage_usec 差值计算，不含板上 SSH 进程与 Windows 解码进程。结果来自低动态画面短测，无法推断复杂视频、长时负载或最大并发。Y4 未做实机验证。
